50 improvements

Pipeline

  1. rdw pipe --filter CMD — attach an external filter (any shell command reading stdin, writing stdout) to the pipeline at runtime
  2. Named filter presets stored server-side, applicable per-pane via POST /api/v1/panes/{id}/filters
  3. Filter introspection endpoint — GET /api/v1/panes/{id}/filters lists active stages
  4. Backpressure from the WebSocket Hub to slow pipelines instead of silent line drops
  5. Per-pane overflow policy configurable at pane creation: drop-oldest, drop-newest, block
  6. Per-TargetID rate limit to prevent one noisy source from starving others
  7. Line batching — flush multiple lines in a single WebSocket frame when source rate exceeds 60 fps
  8. rdw pipe --replay FILE [--speed N] — replay a saved log at wall-clock or Nx speed

Browser SPA

  1. Dark/light theme toggle, defaulting to prefers-color-scheme
  2. Per-pane font size and font family, adjustable in the browser
  3. Pane-scoped search — current / searches all panes; add a flag to scope to the focused pane
  4. Search history — up-arrow in the search input recalls previous patterns
  5. Highlight rules applied live as new lines arrive, not only on hl: sequence arrival
  6. Pane timestamp overlay toggle from the browser UI
  7. Copy-to-clipboard button per pane
  8. Pane pinning — keep a pane visible across window switches
  9. WebSocket connection status indicator in the window header
  10. Unread badge on window tab when new lines arrive in a non-active window
  11. Mobile-responsive layout — single-column on narrow viewports
  12. Keyboard binding help overlay (? key) rendered as a table — currently absent from the SPA

Layout

  1. Layout import by file drag-and-drop in the browser
  2. Layout diff view — show what changed when layout apply is called
  3. Named layout snapshots with timestamps, not just a flat name map
  4. Pane group collapse/expand in the browser without closing panes
  5. Grid snap-to-percent during gutter drag
  6. Layout templates — predefined skeletons selectable from the browser (2-col, dashboard, etc.)
  7. Per-window pane count limit as a layout field, not a global constant

KV store

  1. KV change notifications over WebSocket — subscribe to a key prefix and receive updates
  2. Per-key TTL with automatic expiry
  3. KV namespace operations — list all keys under a prefix, delete-all for a namespace
  4. KV import/export endpoint — JSON dump and restore of all keys
  5. KV size and entry count reported in GET /api/v1/session

Auth and security

  1. Read-only token scope — allows stream viewing but no mutations
  2. Token rotation — atomically create a replacement and revoke the old in one call
  3. HTTPS support — configurable cert path or auto-generated self-signed cert
  4. CORS origin allowlist in config for cross-origin browser access
  5. Rate limit configuration in config.yaml — currently hardcoded at 10 req/min
  6. Audit log — append-only record of all auth events and API mutations

Export and formatters

  1. PDF export via headless Chromium or wkhtmltopdf
  2. HTML export — self-contained file including the SPA for offline replay
  3. JSON Lines formatter — one collapsible tree per line
  4. Diff formatter — unified diff between consecutive JSON or text snapshots
  5. SQL formatter with syntax highlighting
  6. Image slideshow mode — cycle multiple b64: frames in the same pane

Operations

  1. SIGHUP config reload without restart
  2. Prometheus metrics endpoint — line counts per pane, connection count, KV size
  3. Structured JSON server log with configurable level
  4. Session persistence — save and restore the full window/pane layout across restarts
  5. rdw server start --demo — start with synthetic data for UI testing

Protocol

  1. rdw pipe reconnect with exponential backoff instead of a fixed 2-second interval
